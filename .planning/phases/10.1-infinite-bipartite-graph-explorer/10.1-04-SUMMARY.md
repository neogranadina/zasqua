# Phase 10.1 Plan 04: Verification, Freeze Diagnosis, and Free-Form Shakedown — Summary

One-liner: What was meant to be a verification checkpoint surfaced an initial-load freeze, and remediation snowballed into a full UX redesign delivering a production-ready /entidades/ explorer with focal-uncap, document-scoped role facet, infinite trail, viewport filter, and a clean two-row layout.

## What Was Built

This plan was scoped as a human verification step. In practice it became the workhorse for everything between "verified working" and "ready to ship". Below is the delta from Plan 03's wired-up state to the final shipped explorer.

### Freeze diagnosis and fix (committed in ba1624e, before today's shakedown)

The browser hung for ~40 seconds on first load of `/entidades/`. Root cause: `parseUrlParams` set a default `count:desc` sort even on the empty pre-search state, which caused `pagefind.search(null, { sort: 'count:desc' })` to perform a full 92,042-entity WASM sort before returning. Fix: drop the default sort from `parseUrlParams`, apply `count:desc` only inside `search()` for real searches that already have a query or filter narrowing the candidate set.

A second freeze on background-tab loads was caused by `requestAnimationFrame` being paused in hidden tabs, leaving the explorer permanently stuck on the loading spinner. Replaced with `setTimeout(0)` for the spinner-paint yield.

### Focal entity uncapped (commit 279ee55)

`loadEntity` and `refocusOn` no longer slice docs to `MAX_INITIAL_DOCS=30`. The focal entity now renders all linked documents — matching the entity detail page (`/entidad/{slug}/`). The overflow-node code path is dormant (kept in case lazy paging becomes useful later) since no path now creates overflow nodes.

### Document-scoped role facet on the selected entity card (commit 279ee55)

The original sidebar role facet was conceptually wrong. Role is a per-document relationship (`DescriptionEntity.role` in the backend), not an entity property — having "54,000 mentioned" entities in the sidebar facet was meaningless. The facet was relocated to the selected entity card under the "documentos vinculados" stat, scoped to the focal entity's shard.

The facet UI is built against the Phase 12.1/13 7-group documentary-role taxonomy:

1. **Producción y menciones** — creator, author, editor, publisher, mentioned, subject, official
2. **Correspondencia** — sender, recipient
3. **Atestación notarial** — scribe, witness, notary
4. **Procesos judiciales** — plaintiff, defendant, petitioner, judge, appellant, fiador, apoderado, victim
5. **Familia y sucesión** — heir, albacea, spouse
6. **Transacciones** — grantor, donor, seller, buyer, mortgagor, mortgagee, creditor, debtor
7. **Materiales visuales** — photographer, artist

Empty groups are hidden. With current data, almost everything falls into Production/mentions and Notarial attestation; the rest will populate when Phase 13 imports the new role enums (`fiador`, `apoderado`, etc.) from `pipeline_role_links.json` / `ca_role_links.json`. No restructuring will be needed.

When the user toggles roles, the graph hides docs whose focal-edge role doesn't match. The sidebar `?rol=` URL param, the Pagefind role filter, and the `roles` field on the `onFilterChanged` callback were all removed.

### Force simulation tuning (commit 279ee55)

Newly expanded entity clusters around a doc were bunching up because the global `charge=-20` (set per D-41 to keep the focal doc ring compact) was too weak to push 10–20 entities apart at link distance 20. Fix: per-node and per-link accessors.

- **Charge**: entity nodes get `-120`, doc nodes stay at `-20`
- **Link distance**: 20 for links touching the focal entity (compact ring), 45 elsewhere (breathing room for trail clusters)

The focal ring stays tight; expanded entity clusters fan out properly.

### Truly infinite trail (commit 4be4dc8)

`MAX_EXPAND_ENTITIES` was removed entirely. Distribution check before deciding: of 88,273 docs in the corpus, only **1** has more than 200 connected entities (210, the worst case ever); only 11 break 100; 99% have ≤20. The "pathological case" essentially doesn't exist, so the cap was pure overhead.

`MAX_HOPS` was raised from 3 to **50** — a long-session safety valve rather than a per-trail limit. A natural exploration trail will never hit it, but after very deep navigation through unconnected branches the prune still cleans up the truly forgotten ones.

When prune does fire, it now resets `node.expanded` and `node.expandable = undefined` on docs that lose entities, so the user can re-expand them later when they wander back. Previously the `expanded` flag stuck and the tooltip refused to re-fetch.

A `ReferenceError` from a transient `MAX_HOPS` removal was silently breaking tooltip and hover state on every refocus — caught and fixed during the same change.

### Layout restructure (commit 4be4dc8)

The 3-column single-row layout (filters | results | selected card) became a 2-row grid:

```
┌──────────────────────────────────┬──────────────┐
│  Graph panel (560px)             │  Selected    │
│                                  │  entity card │
│                                  │  (560px,     │
│                                  │  scrolls)    │
├──────────────┬───────────────────┴──────────────┤
│  Filters     │  Entity index (results)          │
│  (280px)     │                                  │
└──────────────┴──────────────────────────────────┘
```

Both top-row children share `border-radius: 12px` and a `560px` height; the card overflows internally. On viewports below 1024px the grid collapses to single-column with order: graph → selected → filters → results.

### First-load empty state (commit 4be4dc8)

The graph no longer auto-loads a curated entity on first visit. Instead, an overlay with a faint pomegranate emblem, an inline-paragraph explainer (in Colombian Spanish), and four example entity links covers the graph panel. Clicking any example calls `refocusOn()` and dismisses the overlay. Deep links (`?entidad=ne-XXX`) bypass the overlay.

Examples curated for variety and substance: Real Audiencia de Quito (353 docs, corporate), Cabildo de Rionegro (324 docs, corporate), José Gabriel Túpac Amaru (64 docs, person — chosen as the richest Indigenous figure in the corpus), Simón Bolívar (3,641 docs, person — useful for facet-narrowing demos).

### Browse-prompt parity with description search (commit 4be4dc8)

The entity-explorer browse prompt was extended to match `search.js`:

- New "filter-overload" mode triggers when no text query, ≥1 active filter, and `estimateFilterCount() > 10000`. Skips the slow Pagefind WASM scan and shows the same warning prompt as the description-search ("X entidades coinciden con estos filtros" / "Agrega más términos o filtros" / "Ver todos" / "Tomará algunos segundos en cargar")
- The pre-search landing prompt also gained the warning paragraph for visual consistency
- `estimateFilterCount` mirrors `search.js#estimateFilterCount` — sums global facet counts for active filter values per facet, takes the smallest as upper bound

### Viewport filter polish (commit 4be4dc8)

The "Filtrar por vista del explorador" toggle had two bugs and was visually misplaced:

1. **Toggle was overlaid on the graph panel** where the canvas absorbed clicks. Moved into the filter column above the search bar, with a vertical-arrows SVG icon symbolising the link between the graph (top row) and the index (bottom row).
2. **Overload threshold was tripping** when only viewport mode was active because `estimateFilterCount()` returned the global total. Added an `onlyViewportActive` check that bypasses the threshold guard for viewport-only mode (which doesn't go through Pagefind anyway).
3. **Sidebar facets weren't narrowing** in viewport-only mode because the fast path passed `globalFilters` instead of computing scoped counts. Added local facet synthesis from the visible-entity set: entity_type, year, century, decade. Empty facets disappear; counts reflect only visible entities.

### Entity click tooltip (commit 4be4dc8)

Clicking a non-focal entity used to refocus immediately. Now it opens a tooltip with type badge, name, ID, doc count, and a single **"Seleccionar y desplegar vínculos"** action button — mirroring the doc-click "Desplegar" pattern. The user has to confirm before the graph re-pivots. The focal entity gets the same tooltip without the action button (it's already centered).

## Verification of Original Success Criteria

Plan 04's original 7 must-haves, after the shakedown:

| # | Criterion | Status |
|---|---|---|
| 1 | Graph-dominant layout fills viewport from breadcrumb to bottom | **Superseded** — user requested scroll-page layout instead of viewport-filling. Replaced with 2-row grid (graph + card top, filters + index bottom). |
| 2 | One entity plus its documents render as bipartite nodes on page load | **Superseded** — first load now shows the empty-state overlay with example links, by user request. Bipartite render fires on first interaction. |
| 3 | Entity-document-entity chain navigation works at least 3 hops deep | ✅ **Met and exceeded** — trail is now truly infinite (MAX_HOPS=50 as safety valve only). |
| 4 | Simulation runs smoothly without freezing, jarring jumps, or sudden zooming | ✅ **Met** — initial-load freeze fixed (default-sort root cause), expanded-cluster bunching fixed (per-node charge tuning). |
| 5 | Role filter pills toggle graph edge visibility and sidebar results | **Superseded** — role moved out of the entity-list facet into the selected-entity card. Document-scoped, per the actual data model. |
| 6 | Entity index sidebar allows search/browse with Pagefind facets | ✅ **Met** — entity_type, primary_function, and date facets all work; counts narrow scoped to active filters. |
| 7 | Clicking an entity in the graph updates the sidebar focal card | ✅ **Met** — bidirectional sync via `onEntityFocused` callback, plus shard data passed through for the role facet. |

Three superseded criteria represent user-driven scope changes during the shakedown, not regressions. The phase successfully delivered the original goal (production-ready bipartite explorer for `/entidades/`) and went substantially beyond it.
