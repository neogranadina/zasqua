<decisions_made>

1. **Roles aggregated at build time** from `data/entity_links.json` because the backend export leaves `entity.roles` empty for all 92k entities. Each entity now gets `entity.roles = [...distinct sorted roles]` before page generation, so the entity Pagefind index gets a proper `role` filter dimension.

2. **Century and decade dedicated Pagefind filters** added to `src/entidad.njk` (one span per century and per decade an entity spans). The previous year-only spans inflated century counts because a 60-year-lived entity contributed 60 to its century total. New filters give accurate unique-entity counts at each aggregation level.

3. **Layout pivoted from viewport-filling app shell to scroll-page 3-column** per the EntityExplorerRefinedPage Make spec. Not a literal port — adopted structure and styling, kept the rich infinite-bipartite-explorer (not the SVG mock), kept the date hierarchy (century→decade→year tree), kept role pills (just moved them into the filter sidebar as a checkbox group instead of a pill bar above the results column).

4. **`.container` dropped from explorer-page wrapper.** Tailwind v4's `.container` utility lives in `@layer utilities` and beats any component-layer rule regardless of selector specificity. Standalone `.explorer-page` class with `max-width: var(--max-width)` is the only reliable workaround.

5. **`requestAnimationFrame` replaced with `setTimeout` in `entity-explorer.search()`.** rAF is paused in hidden tabs, leaving the explorer permanently stuck on the loading spinner when users open `/entidades/` in a background tab and switch to it later. setTimeout(0) fires regardless of visibility.

6. **Default sort moved from `parseUrlParams` into `search()` proper.** The default `count:desc` was tripping the pre-search guard and triggering a full 92k WASM sort on initial page load (~40 second freeze). Default sort still applies for real searches, just not on the empty browse-prompt state. This was the root cause of the 10.1-04 verification blocker.

7. **Viewport-only render path bypasses Pagefind entirely.** When the user toggles "Filtrar por vista del explorador" with no other filters active, an unfiltered Pagefind query on the 92k entity index blocks the WASM thread for tens of seconds even unsorted. The visible viewport is at most ~100 entities, so we synthesise Pagefind-style hit objects from `getVisibleEntities()` and let `renderResultCard` render them. Sort happens client-side. When viewport is combined with other facets, the Pagefind path is still used and post-filters by visible code set.

8. **Role facet rendered as checkbox group in left filter sidebar** instead of as a pill bar above the results column. User feedback: roles should match the visual language of type/date facets. Multi-select preserved via `activeRoles` set. Latent bug fixed: `hasActiveFilters` was missing `state.role`, which caused role-only filters to fall through to the browse-prompt branch.

9. **Dark hover tooltip variant** added via `.graph-tooltip.is-hover` modifier. Click tooltip keeps light styling and takes priority — while a click tooltip is open the hover handler bails out so it doesn't overwrite the click content.

10. **Eager doc-node expandability resolution** ported from `entity.js`. After each `addNodesToGraph`, walk the freshly added doc nodes and query Pagefind's descriptions index sequentially to find which docs have further entity links. Cache the result so the existing lazy hover lookup short-circuits, and skip nodes pruned mid-resolution to play nicely with refocus.

## Critical Anti-Patterns (do NOT repeat these)

- **WASM-blocking Pagefind queries**: any `pagefind.search(null, {sort: ...})` on the 92k entity index will block the WASM thread for ~40 seconds and freeze the page. The pre-search guard in `search()` MUST stay correct: never let it fall through with no filters and no query. If you need to render an unfiltered result set, use the viewport-only fast path or render from in-memory data.
- **`requestAnimationFrame` await for spinner paint**: rAF is paused in hidden tabs. Always use `setTimeout(r, 0)` for the spinner-paint yield.
- **`.container` for the explorer page**: Tailwind v4's `.container` utility wins because it lives in `@layer utilities`. Use `.explorer-page` standalone with explicit max-width.
- **Editing rendered HTML in `_site/entidades/index.html` AND running eleventy in parallel**: the build will silently overwrite your edits. Either fully edit the source and rebuild, or fully edit the rendered HTML. Don't mix without coordinating.
- **`_redraw()` on every hover**: re-applying graphData to the force-graph instance perturbs the d3 simulation and causes nodes to wiggle. The continuous simulation already redraws every frame.

## Infrastructure State

- **http-server on :8080** with `-c-1` (no cache) — running from a previous session, serves `_site/`. Confirm still running before resuming.
- **Tailwind not in `npm run build`**: CI runs `tailwindcss-linux-x64 -i src/css/input.css -o src/css/main.css --minify` as a separate binary step. Locally we run `npx @tailwindcss/cli -i src/css/input.css -o src/css/main.css --minify` after CSS changes. Don't forget this step or CSS won't update.
- **Eleventy build is heavy**: ~8 minutes for the full 92k entity pages + 3 Pagefind passes. Use `NODE_OPTIONS="--max-old-space-size=8192"` to avoid OOM. Single-file rebuilds are not really supported (layouts depend on full project context).
