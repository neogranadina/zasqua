# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Never run `pagefind.search(null, { sort: ... })` against the entity index** — sorting an unfiltered query across all 92,042 entities takes 24+ seconds and hangs the Pagefind WASM thread. While that query is in flight, every other Pagefind call queues behind it, making the page appear to crash. The structural mitigation is: never call `pagefind.search()` with `null`/empty query AND a sort option. Always require either a query string or a filter narrow enough to keep results bounded. The current code has a `browsePrompt: true` branch that avoids this — preserve it.

- [ ] CONSTRAINT: **`graphInstance.refresh()` does NOT exist on the standalone (non-3D) force-graph build.** Use the `_redraw()` helper that re-applies `graphData()`. Calling `.refresh()` throws TypeError silently and breaks every code path that depends on it (hover, filter, expand, prune).

- [ ] CONSTRAINT: **All sizes drawn in `nodeCanvasObject` MUST be divided by `globalScale`.** force-graph pre-applies the zoom transform to the canvas context, so a circle of radius 12 in world coordinates renders at `12 * globalScale` screen pixels. Use `r = SCREEN_PX / globalScale` everywhere. Hit areas in `nodePointerAreaPaint` MUST use the same screen-space sizes or clicks will miss the visible nodes.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Unbounded Pagefind sort | `pagefind.search(null, {sort: count:desc})` against 92k entities hung WASM for 24s, blocking all subsequent calls | blocking | Code path must never issue a sort query without a filter that bounds results to <1k. The browsePrompt branch in EntityExplorer.search() handles this — keep it. |
| `function(l){this...}` callbacks | rebuildAdjacency used a non-arrow callback inside forEach where `this` was undefined; threw silently after every addNodesToGraph call, breaking adjacency | blocking | Use arrow functions or `.bind(this)` for inner callbacks. Any new code in infinite-bipartite-explorer.js that touches `this` inside a callback must be reviewed. |
| World-coord node sizes | All radii in drawNode were specified in world coordinates; force-graph scales them by globalScale, producing 100+px circles when zoomed in | advisory | All drawNode sizes are now `SCREEN_PX / globalScale`. Hit-area paint must match. Document this convention in code comments. |
| Concatenated tooltip buttons | Two `<a class="graph-tooltip-btn">` elements rendered inline with no separator → "DesplegarVer descripción" mash-up | advisory | Match entity.js tooltip pattern: title is `<a>` link inside `.graph-tooltip-name`, action button(s) live in a separate `.graph-tooltip-actions` wrapper appended async. |
| Sync 5.7 MB fetch at init | desc-entity-lookup.json was loaded upfront on every page load to enable expandability checks | advisory | Use lazy Pagefind-based lookup matching entity.js pattern. Cache results in `expandableCache` per refCode. |
