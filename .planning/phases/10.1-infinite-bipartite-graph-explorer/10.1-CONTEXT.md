# Phase 10.1: Infinite Bipartite Graph Explorer - Context

**Gathered:** 2026-04-05 (assumptions mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the entity explorer's curated 100-node graph with an infinite bipartite graph explorer. Users start with one entity and its linked documents as nodes, then navigate entity→document→entity chains indefinitely. The graph viewer dominates the page layout (like the place explorer map). An entity index sidebar allows search/browse and syncs with graph state. Facets filter both graph and index.

</domain>

<decisions>
## Implementation Decisions

### Data Loading Strategy
- **D-01:** Load entity-link shards on demand via fetch (`/data/entity-links/{code}.json`) for entity→document links
- **D-02:** Resolve document→entity connections via Pagefind descriptions index (`hit.filters.entidad`), reusing the proven pattern from `entity.js:439-761`
- **D-03:** Cache fetched shards in a Map to prevent redundant network requests (same as `entity.js` shardCache)

### Graph Library & Simulation
- **D-04:** Use the same force-graph library (vasturiano) loaded via CDN — no library change
- **D-05:** Continuous simulation that never fully cools — no `cooldownTime` cutoff, no `onEngineStop(zoomToFit)`. Nodes settle naturally and remain interactive
- **D-06:** Starting parameters from entity.js: `d3AlphaDecay(0.02)`, `d3VelocityDecay(0.3)`, charge strength `-20`, link distance `20` — tune empirically for smooth feel
- **D-07:** Use `d3ReheatSimulation()` when adding new nodes (proven in `entity.js:753`), positioning new nodes near their parent to avoid jarring jumps
- **D-08:** Enable node drag with `onNodeDragEnd` pinning (`node.fx = node.x`) — same as entity.js

### Page Layout
- **D-09:** Graph canvas dominates the viewport — similar to how the place explorer map fills the content area
- **D-10:** Entity index lives in a sidebar panel (narrow, on the left) — keeps the Pagefind entity search, facets, and paginated results
- **D-11:** Replaces the current independent graph-above + explorer-below arrangement entirely

### Starting State
- **D-12:** On load, show ONE entity (the most connected from the curated graph, ne-69501) plus its linked documents as bipartite nodes
- **D-13:** Cap initial document nodes at ~30 (most recent by date), with a visible indicator showing "N more documents — click to expand"
- **D-14:** The starting entity can be overridden via URL parameter (`?entidad=ne-12345`)

### Node Interaction (replicating entity.js patterns)
- **D-15:** Click entity node → tooltip with type, name, code, connection count, "Ver ficha completa" link. Same as entity.js `showEntityTooltip`
- **D-16:** Click document node → tooltip with date, role, title, reference code, "Desplegar" expand button. Same as entity.js `showDocTooltip`
- **D-17:** Click "Desplegar" on document → loads that document's entity connections via Pagefind, adds new entity nodes to graph. Same as entity.js `expandDocument`
- **D-18:** Click entity node (when it's not the focal entity) → could refocus the graph on that entity, loading its documents. This is the key new behaviour enabling infinite navigation
- **D-19:** Hover → highlight node + neighbours, dim everything else. Same as entity.js hover pattern
- **D-20:** Labels shown only on hover or zoom (globalScale > 1.2). Same as entity.js

### Facet Filtering
- **D-21:** Separate facet domains: sidebar facets (entity type, function, date) control the entity index only
- **D-22:** Graph-specific role filter pills (Productor, Materia, Mencionado, etc.) control graph edge visibility — same pattern as entity.js role filters
- **D-23:** When a role filter hides all edges for a node, that node fades. Same as entity.js
- **D-24:** Clear visual separation between sidebar facets and graph role filters prevents confusion

### Node Management (preventing hairball)
- **D-25:** Track distance from focal entity (hops). When refocusing on a new entity, offload nodes > 3 hops away to keep graph size manageable (~50-80 nodes max)
- **D-26:** "Refocus" action: when user clicks an entity and chooses to explore it, that entity becomes the new centre — its shard is loaded, its documents appear, and distant nodes from the previous focus are pruned

### Visual Style (matching entity.js)
- **D-27:** Entity node colours: person=#8B2942, corporate=#6666BB, family=#6666BB — same as entity.js
- **D-28:** Document nodes: small stone dots (#A09888), filled if expandable, hollow outline if not — same as entity.js
- **D-29:** Entity node size scales with degree/linked count — same as entity.js
- **D-30:** Graph container uses `.entity-graph-frame` styling (border, border-radius, bg-stone-50) — matching entity detail page

### Claude's Discretion
- Exact simulation parameter tuning for smooth feel
- Mobile/responsive behaviour (graph toggle, sidebar collapse)
- Tooltip positioning and z-index management
- How the "N more documents" expand indicator looks
- Animation timing for node addition/removal
- Whether to show the graph legend inside or outside the frame

</decisions>

<specifics>
## Specific Ideas

- "I want you to create a version of the entity graph view that permits users to follow entity>document>entity>document chains indefinitely"
- "Because the graph will be the focus, the graph should be the primary focus of the page — just as the map is the primary focus of the place explore interface"
- "I want centering a new entity to pull up that entity in the index"
- "I want to remove these stupid jittery jumps and sudden zooming"
- "On load, I just want you to show me ONE entity — pick whatever, it could be the most connected — and the documents it is connected to"
- The entity detail page graph (entity.js) is the proven interaction model — replicate its tooltips, hover, expand, and visual style
- "I want to approximate the Obsidian graph view" — referring to the always-alive, smooth simulation where nodes settle naturally

</specifics>
