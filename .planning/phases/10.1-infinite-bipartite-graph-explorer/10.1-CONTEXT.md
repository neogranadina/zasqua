# Phase 10.1: Infinite Bipartite Graph Explorer - Context

**Gathered:** 2026-04-05 (updated from discuss mode)
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the entity explorer's curated 100-node graph with an infinite bipartite graph explorer. Users start with one entity and its linked documents as nodes, then navigate entity→document→entity chains indefinitely. The graph viewer dominates the page layout. A combined sidebar provides filters (role pills, facets) and an entity index (search/browse). Facets and search filter both graph and index bidirectionally.

</domain>

<decisions>
## Implementation Decisions

### Page Layout
- **D-01:** Combined [Filters + Index] sidebar on the left, graph fills the rest (~68% viewport width). Two-column layout, not three
- **D-02:** Sidebar is always visible — not collapsible
- **D-03:** Fixed split in the sidebar: filter section at the top, entity index fills the rest below. Simple divider line
- **D-04:** Minimal page header — just the breadcrumb. Title "Explorar entidades" moves into the sidebar or disappears. Graph starts higher
- **D-05:** Full viewport height — graph and sidebar fill from breadcrumb to bottom of the viewport. No page scrolling. Only sidebar panels scroll internally
- **D-06:** This is a viewport-filling app layout, not a scrollable page — a significant departure from the current page-style layout

### Filter Panel (top of sidebar)
- **D-07:** Role filter pills live in the filter section of the sidebar, above entity type/function facets. Not on the graph canvas
- **D-08:** Sidebar facets (entity type, function, date range) filter BOTH the graph AND the entity index — unified filtering
- **D-09:** Role pills also filter both graph and index — same unified behaviour
- **D-10:** When facets/filters are applied, graph nodes that don't match animate: fade and shrink out, then are removed from simulation. Restored nodes fade in

### Entity Index (bottom of sidebar)
- **D-11:** Entity index keeps the Pagefind entity search, faceted results, and pagination from EntityExplorer. Searches all 83K entities via pagefind-entities index
- **D-12:** No separate document results panel — document info only appears as tooltips when users click doc nodes in the graph viewer

### Graph↔Sidebar Sync (fully bidirectional)
- **D-13:** Graph→Index: when user refocuses on an entity in the graph, a focused entity card appears at the top of the index panel showing entity details (name, type, dates, doc count), AND the entity is highlighted/scrolled-to in the result list below (filters cleared if necessary)
- **D-14:** Index→Graph: clicking an entity in the sidebar index centres and loads it in the graph — pans to it if already loaded, loads its shard and adds it as focal entity if not
- **D-15:** Search→Graph: typing in the index search filters the graph — only matching entity nodes (and their connected docs) remain visible. Non-matching nodes are hidden entirely. Graph restructures around the matches
- **D-16:** Unloaded matches: index shows all Pagefind matches (paginated as usual). Graph only highlights/filters the subset already loaded. Clicking an unloaded match in the index loads it into the graph
- **D-17:** Clear filters: restoring filters brings back all previously loaded nodes (within hop-distance pruning limit). Full exploration state returns — within reason
- **D-18:** URL updates on every refocus: `?entidad=ne-12345` param updates when the focal entity changes. Back button navigates graph history. Shareable/bookmarkable links
- **D-19:** Starting entity can be overridden via URL parameter (`?entidad=ne-12345`)

### Data Loading Strategy
- **D-20:** Load entity-link shards on demand via fetch (`/data/entity-links/{code}.json`) for entity→document links
- **D-21:** Cache fetched shards in a Map to prevent redundant network requests (same as entity.js shardCache)
- **D-22:** Document→entity reverse lookup strategy is Claude's discretion (options: Pagefind descriptions index, desc-entity-lookup.json, or pre-computed reverse shards)

### Starting State
- **D-23:** On load, show ONE entity (most connected, ne-69501) plus its linked documents as bipartite nodes
- **D-24:** Cap initial document nodes at ~30 (most recent by date), with a virtual '...' overflow node showing "+N more documents — click to expand"

### Node Interaction
- **D-25:** Click entity node → tooltip with type, name, code, connection count, "Ver ficha completa" link. Same as entity.js `showEntityTooltip`
- **D-26:** Click document node → tooltip with date, role, title, reference code, "Desplegar" expand button AND "Ver descripcion" link (opens in new tab)
- **D-27:** Click "Desplegar" on document → loads that document's entity connections, adds new entity nodes to graph
- **D-28:** Click entity node (not focal) → refocuses the graph on that entity, loading its documents. Key behaviour enabling infinite navigation
- **D-29:** Hover → highlight node + neighbours, dim everything else. Same as entity.js hover pattern
- **D-30:** Labels shown only on hover or zoom (globalScale > 1.2). Same as entity.js

### Document Node Visual States (three states)
- **D-31:** Small hollow circle — document has no further entity connections (terminal node)
- **D-32:** Small filled circle — document has entity connections that can be loaded (expandable)
- **D-33:** Larger filled circle — document has been expanded (its entity connections are already loaded). Size change signals "this has been explored"

### Document Expansion Caps
- **D-34:** When expanding a document node, cap at ~15 entity connections (top by relevance or frequency). Show "+N more entities" indicator
- **D-35:** Virtual '...' overflow node shows count of hidden documents ("+170 docs"). Clicking loads the next batch of ~30. Progressive batches — node updates its count after each batch

### Node Management (preventing hairball)
- **D-36:** Track distance from focal entity (hops). When refocusing on a new entity, offload nodes > 3 hops away to keep graph size manageable (~50-80 nodes max)
- **D-37:** "Refocus" action: entity becomes the new centre, its shard loads, its documents appear, distant nodes from previous focus are pruned
- **D-38:** Auto-reload on return: when user refocuses on a previously-visited entity, its documents reload from the cached shard. Pruned nodes come back seamlessly

### Graph Library & Simulation
- **D-39:** Use the same force-graph library (vasturiano) loaded via CDN — no library change
- **D-40:** Continuous simulation that never fully cools — no `cooldownTime` cutoff, no `onEngineStop(zoomToFit)`. Nodes settle naturally and remain interactive
- **D-41:** Starting parameters from entity.js: `d3AlphaDecay(0.02)`, `d3VelocityDecay(0.3)`, charge strength `-20`, link distance `20` — tune empirically
- **D-42:** Use `d3ReheatSimulation()` when adding new nodes, positioning new nodes near their parent
- **D-43:** Enable node drag with `onNodeDragEnd` pinning (`node.fx = node.x`)

### Visual Style (matching entity.js)
- **D-44:** Entity node colours: person=#8B2942, corporate=#6666BB, family=#6666BB
- **D-45:** Document nodes: stone dots (#A09888), with three visual states per D-31/D-32/D-33
- **D-46:** Entity node size scales with degree/linked count
- **D-47:** Graph container uses `.entity-graph-frame` styling (border, border-radius, bg-stone-50)

### Transition from Curated Graph
- **D-48:** Full replacement of CuratedEntityGraph — delete `src/js/curated-entity-graph.js` entirely
- **D-49:** Delete `src/js/entity-network-graph.js` (already dead code, not loaded in any template)
- **D-50:** `src/js/entity.js` on entity detail pages is untouched — different use case

### Data Pipeline Changes
- **D-51:** Update `build.sh` to run three Pagefind passes matching CI (`pagefind/`, `pagefind-entities/`, `pagefind-places/`), so local dev matches production
- **D-52:** Remove `scripts/precompute-cooccurrence.js` and its step from build.sh — co-occurrence data no longer needed
- **D-53:** Remove `scripts/precompute-curated-graph.js` and its step from build pipeline
- **D-54:** Add role as a Pagefind filter on entity pages — all roles the entity appears in across all linked documents. Enables role-based faceting in the sidebar across all 83K entities
- **D-55:** Build the pipeline infrastructure now with current entity data. Role/function data is being cleaned up in zasqua-entities — quality will improve when that enrichment lands. No blocker

### Claude's Discretion
- Document→entity reverse lookup implementation strategy (Pagefind vs desc-entity-lookup.json vs reverse shards)
- How to pick the default starting entity (keep curated JSON for degree data, new lightweight file, or hardcode)
- Whether Pagefind entity index needs additional changes beyond role filter
- Facet count display strategy (Pagefind totals vs graph-aware counts vs both)
- Exact simulation parameter tuning for smooth feel
- Mobile/responsive behaviour (graph toggle, sidebar collapse)
- Tooltip positioning and z-index management
- How the virtual "..." overflow node looks visually
- Animation timing for node addition/removal
- Whether to show the graph legend inside or outside the frame
- URL parameter name (?entidad= vs ?nodo=)

</decisions>

<specifics>
## Specific Ideas

- "I want you to create a version of the entity graph view that permits users to follow entity>document>entity>document chains indefinitely"
- "Because the graph will be the focus, the graph should be the primary focus of the page — just as the map is the primary focus of the place explore interface"
- "I want centering a new entity to pull up that entity in the index"
- "I want to remove these stupid jittery jumps and sudden zooming"
- "On load, I just want you to show me ONE entity — pick whatever, it could be the most connected — and the documents it is connected to"
- "I want to approximate the Obsidian graph view" — referring to the always-alive, smooth simulation
- The entity detail page graph (entity.js) is the proven interaction model — replicate its tooltips, hover, expand, and visual style
- Layout exploration via playground confirmed: combined sidebar left, graph right, viewport-filling
- Document info appears ONLY as tooltips on doc nodes — no separate document browser panel
- Role/function data is being actively enriched in zasqua-entities — build infrastructure now, data quality improves later

</specifics>
