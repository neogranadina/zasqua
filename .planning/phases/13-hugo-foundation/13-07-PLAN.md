<deliberate_divergences>
Three documented adaptations. None changes the visual output against production data.

1. **Number formatting.** Eleventy's `numberFormat` filter (eleventy.config.js:68) does:
   ```js
   num.toString().replace(/\B(?=(\d{3})+(?!\d))/g, ".");
   ```
   Hugo equivalent: `{{ lang.FormatNumberCustom 0 $count "" "," "." }}` — 0 decimals, Latin convention (`.` thousands, `,` decimal). For the description_count integers in repositories.json (55359, 276, 10569, 14776, 25549), output matches byte-for-byte: `55.359`, `276`, `10.569`, `14.776`, `25.549`.

2. **sortByOrder filter.** Eleventy's `sortByOrder` (eleventy.config.js:73) sorts an array by the index of each item's `code` in a given order array. In Hugo, we iterate the order array and look up each code with `where`:
   ```gotmpl
   {{ $order := slice "pe-bn" "co-ahjci" "co-ahr" "co-ahrb" "co-cihjml" }}
   {{ range $code := $order }}
     {{ $repo := index (where $repos "code" $code) 0 }}
     ...
   {{ end }}
   ```
   Produces repos in identical order to Eleventy.

3. **Repository data source.** Eleventy reads `exports/repositories.json` via `src/_data/repositories.js`. Hugo reads `assets/hugo-data/repositories.json` via `resources.Get "hugo-data/repositories.json" | transform.Unmarshal`. The JSON content is byte-identical — Task 1 copies the file verbatim. Choice of path (`assets/hugo-data/`) matches the Phase 13 convention for Hugo-consumed enrichment output, per 13-03 CONTEXT §D-03.

No per-repo override data (images, subtitles, category labels, link overrides) comes from the JSON — those are hardcoded in the Eleventy template and preserved as-is in the Hugo port, since that's what the source does.
</deliberate_divergences>
