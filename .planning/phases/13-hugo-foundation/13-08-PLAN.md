<deliberate_divergences>
Three documented adaptations, none affecting rendered visual output.

1. **Routing: pagination → content adapter.** Eleventy's `src/repository.njk` uses front-matter `pagination: { data: repositories, size: 1, alias: repo }` + `permalink: "/{{ repo.code }}/"` to spin up one page per repo. Hugo's equivalent is the content-adapter pattern already established for descripcion/entidad/lugar in Plan 13-03: iterate the JSON data and `AddPage` with an explicit `url` override. Same URL scheme produced, same data available to the template via `.Params`.

2. **numberFormat → lang.FormatNumber.** Same as Plan 13-07 — site locale es-CO produces Latin American `.` thousands separator. Byte-equivalent output for displayed integers.

3. **ui.levelsPlural JSON serialisation.** Ported with the same `{{ printf `data-level-labels='%s'` (jsonify hugo.Data.ui.levelsPlural) | safeHTMLAttr }}` pattern proven in Plan 13-06 for buscar — raw JSON in raw double-quotes, no HTML-entity escapes. Key ordering will be alphabetical (Hugo's jsonify) vs YAML source order (Eleventy's dump); functionally identical per same reasoning as 13-06.
</deliberate_divergences>

<!-- content/repository/_content.gotmpl — content adapter following the same pattern Plan 13-03 used for descripcion/entidad/lugar -->

```gotmpl
{{/*
  Zasqua repository content adapter

  Runs during Hugo's content-loading phase, reads
  assets/hugo-data/repositories.json (copied verbatim from
  exports/repositories.json by scripts/generate-content.js), and calls
  AddPage once per repository record so Hugo registers every
  repository landing as a routable page.

  URL scheme: /{code}/ per D-18 (flat short-codes). This override is
  applied via the `url` field on the page dict — the same technique
  Plan 13-03's descripcion/entidad/lugar adapters use to override
  the /repository/ section prefix.

  Data shape (per record in repositories.json): code, name,
  description_count, country_code, country, city, root_descriptions
  (array of fonds-level description stubs).

  Layout resolution: Hugo uses layouts/repository/single.html because
  the page's internal kind is "page" and its section is "repository".

  Version: v1.0.0
*/}}

{{ $data := slice }}
{{ with resources.Get "hugo-data/repositories.json" }}
  {{ with try (. | transform.Unmarshal) }}
    {{ with .Err }}
      {{ errorf "[repository adapter] Unable to parse repositories.json: %s" . }}
    {{ else }}
      {{ $data = .Value }}
    {{ end }}
  {{ end }}
{{ end }}

{{ if not $data }}
  {{ errorf "[repository adapter] No repository data found at assets/hugo-data/repositories.json — has scripts/generate-content.js run yet?" }}
{{ end }}

{{ range $data }}
  {{ $params := dict
      "code" .code
      "name" .name
      "description_count" .description_count
      "country" .country
      "country_code" .country_code
      "city" .city
      "root_descriptions" .root_descriptions
  }}
  {{ $page := dict
      "kind" "page"
      "path" .code
      "title" .name
      "params" $params
      "content" (dict "mediaType" "text/html" "value" "")
  }}
  {{/* D-18: flat-code URL override */}}
  {{ $page = merge $page (dict "url" (printf "/%s/" .code)) }}
  {{ $.AddPage $page }}
{{ end }}
{{/* Version: v1.0.0 */}}
```

**Note on the embedded JSON script tag:** Eleventy uses `{{ repo.root_descriptions | dump | safe }}` inside `<script type="application/json">`. In script-tag context, the content is NOT attribute-escaped — `safeJS` is the right marker because the browser parses the script content as JSON text with raw double quotes preserved. If `safeJS` over-escapes or under-escapes, fall back to `safeHTML`.
