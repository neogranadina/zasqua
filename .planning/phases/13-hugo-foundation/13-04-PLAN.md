<objective>
Relocate every static asset from `src/` to the Hugo canonical directory structure so subsequent plans (13-05 base layout onwards) can reference them at their existing URLs without any template-side URL changes.

This plan does NOT touch any template, content adapter, layout, partial, configuration file, or data file. It is a pure file move operation plus one CSS file creation. It ends with a smoke check that confirms assets are reachable.
</objective>

<scope>
## In scope

- `git mv` of `src/js/` → `static/js/` (nine JavaScript files, byte-identical)
- `git mv` of `src/vendor/tify/` → `static/vendor/tify/` (two files)
- `git mv` of `src/img/` → `static/img/` (seventeen image files)
- Creation of `assets/css/main.css` by prepending a Tailwind v4 preamble (narrative header + `@import "tailwindcss";` + `@source "hugo_stats.json";`) to the content of `src/css/input.css`
- `git rm` of `src/css/input.css` and `src/css/main.css` (input.css content now lives in `assets/css/main.css`; main.css was the stale compiled Eleventy output and is no longer needed)
- Addition of a version footer to `assets/css/main.css`

## Out of scope (explicitly)

- Any `.njk` template file in `src/_layouts/`, `src/_includes/`, `src/*.njk`, `src/explorar/*.njk` — these stay in place for 13-05 through 13-14 to port from
- `src/_data/` — enrichment script still reads `src/_data/ui.js` for the `roles` map until Plan 13-15 removes `src/` entirely
- `eleventy.config.js` — stays functional so you can still reason about the Eleventy pipeline
- Any Hugo template, layout, partial, or content file
- `hugo.toml`, `package.json`, `build.sh` — unchanged
- Any runtime data shard location decisions (those are a Plan 13-15 concern)

## Out of scope (justified)

Moving assets means the local Eleventy build (`npx @11ty/eleventy`) will fail after this plan, because Eleventy's passthrough directives in `eleventy.config.js` point at `src/js/`, `src/vendor/tify/`, `src/img/`, and `src/css/`. This is acceptable because the A/B baseline for all subsequent plans in this phase is the **live zasqua.org** (current production Eleventy deployment), not a local Eleventy rebuild. zasqua.org continues to serve until Phase 15 deploys the new Hugo pipeline.

If at any point during 13-05 through 13-14 we need to rebuild Eleventy locally for debugging, we can either:
- Checkout a pre-13-04 commit (`abandoned/phase-13-04-first-attempt` tag captures even earlier state)
- Update `eleventy.config.js` passthrough directives to point at the new Hugo paths (trivial if ever needed)
- Accept zasqua.org as the baseline (preferred)
