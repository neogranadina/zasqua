# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: V8 512 MiB max-string-length — a single enriched `descriptions.json` at the 106,529-record scale weighs ~610 MB and cannot be JSON.parsed by any Node consumer (nor `require()`-ed). Plan 13-03's Hugo adapter and every downstream test MUST treat descriptions as a sharded directory (`assets/hugo-data/descriptions/*.json`, fixed-count shards of 20,000 records each). Do not regenerate a single-file descriptions.json under any circumstances. Iterate the directory via glob; do not hard-code shard filenames.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Single unified descriptions.json | Producing one giant enriched file — surfaces at ~512 MiB as `RangeError: Invalid string length` in V8. Discovered during Plan 13-02 full-dataset run. | blocking | `scripts/generate-content.js` now shards by fixed record count; adapters and tests iterate the shard directory. Any code that writes a unified `assets/hugo-data/descriptions.json` must be rejected in review. |
| replace_all on narrative prose | Using `Edit --replace_all` to rename a literal path (e.g. `data/` → `exports/`) also rewrites the literal inside the narrative header's explanatory prose, silently corrupting "renamed from `data/`" into "renamed from `exports/`". | advisory | Prefer a scoped `Edit` around the specific code region; when `replace_all` is needed, spot-check narrative headers afterward. |
