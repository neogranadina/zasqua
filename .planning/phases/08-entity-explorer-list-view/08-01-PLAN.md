**eleventy.config.js** -- Add yearRange custom filter (after the existing `extractYear` filter, around line 88):

```javascript
eleventyConfig.addFilter("yearRange", function(start, end) {
  if (!start) return [];
  const s = parseInt(start, 10);
  if (isNaN(s)) return [];
  const e = end ? parseInt(end, 10) : s;
  const cap = Math.min(e, s + 500);
  const years = [];
  for (let y = s; y <= cap; y++) years.push(y);
  return years;
});
```

Replace the existing "Index with Pagefind" step (line 107-108) in `.github/workflows/deploy.yml` with three separate Pagefind runs. Use `--exclude-selectors` on the description run (more portable than glob negation per Research Open Question 1):

```yaml
      - name: Index with Pagefind
        run: |
          # Run 1: Description search index (exclude entity and place pages)
          npx pagefind --site _site --output-subdir pagefind \
            --exclude-selectors "[data-pagefind-entity-page],[data-pagefind-place-page]"

          # Run 2: Entity explorer index
          npx pagefind --site _site --output-subdir pagefind-entities \
            --glob "entidad/**/*.html"

          # Run 3: Place explorer index
          npx pagefind --site _site --output-subdir pagefind-places \
            --glob "lugar/**/*.html"
```

The description run uses `--exclude-selectors` to skip pages carrying `data-pagefind-entity-page` or `data-pagefind-place-page` marker attributes (added in Task 1). The entity and place runs use `--glob` to target only their respective directories. All three write to separate subdirectories under `_site/`.

Note: `--output-subdir pagefind` on the description run is explicit (previously it was the default). This makes the three-index architecture clear.
