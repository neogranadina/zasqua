### Graph-specific color assignments

**Note:** The graph node and edge palette below is a separate semantic layer from the 60/30/10 UI color contract above. The UI contract governs chrome, surfaces, and interactive controls. The graph palette governs data encoding within the canvas. The shared use of `#8B2942` (`--color-burgundy`) for both the UI accent (role filter checkboxes) and the `person` node fill is intentional — it reinforces the entity type's visual identity — but these are distinct roles in distinct layers and should not be treated as a budget conflict.

## Interaction Contract

### Graph panel layout (D-19)

Primary focal point: the graph canvas, centred in the viewport above the results list.

- **Desktop (≥769px):** Graph panel is full-width, positioned above the results list. Same vertical stacking as the heatmap on `/explorar/lugares/`. No toggle — always visible.
- **Mobile (≤768px):** Graph panel is collapsible. A toggle button `Mostrar / ocultar red` sits above the panel, using the `.mobile-filter-toggle` button style. Panel is collapsed by default on mobile. When collapsed, height is 0 with `overflow: hidden`. When expanded, height is `40vh`.

Toggle button label:
- Collapsed state: `Mostrar red de entidades`
- Expanded state: `Ocultar red de entidades`

### Node interaction (D-04, D-05, D-07)

| Interaction | Behaviour |
|-------------|-----------|
| Hover a node | Show tooltip: entity name (bold 14px) + document count (meta 11px) |
| Single click | Expand 1-hop ego-network — immediate neighbours become full opacity; all other nodes fade to suppressed state |
| Double-click | Navigate to `/entidad/{code}/` — full page navigation |
| Click canvas (no node) | Collapse ego-network — restore all nodes to default opacity |

### Edge interaction (D-13)

| Interaction | Behaviour |
|-------------|-----------|
| Hover an edge | Show tooltip: `{NameA} ↔ {NameB}: {N} documentos` + per-role-pair breakdown (one line each) |

### Filter synchronisation (D-08, D-09)

- When the entity explorer search/facets change, the graph recalculates which nodes match the current result set.
- Matching nodes: full opacity.
- Non-matching nodes: suppressed (fill opacity 0.12, border opacity 0.15).
- Transition: 200ms ease-in-out opacity on both nodes and their connected edges.
- Clicking a graph node does NOT modify the results list state.

### Role filters (D-14, D-15)

- Five checkboxes inside the graph panel (not in the sidebar): Productor, Colaborador, Editor, Materia, Mencionado.
- Unchecking a role hides edges where that role participates.
- When all edges for a node are hidden by role filters, that node fades to suppressed state (no orphan nodes).
- Default: all roles checked.
- Layout: horizontal flex row of checkboxes on desktop; wraps on mobile.

### Zoom and pan controls (Claude's discretion)

- Sigma.js built-in mouse/touch pan and scroll-to-zoom — enabled.
- Reset button: `Restablecer vista` — text button (`.btn-pill` style, stone background) anchored to top-right corner of graph canvas. Resets zoom to fit the current displayed subgraph.
- Animation on ego-network expand: 300ms ease-out camera zoom-to-fit the selected ego-network.

### Starter network (D-02)

- On initial page load (no search active), the graph shows the top ~100 nodes by edge degree.
- These nodes are identified client-side from the full `entity-cooccurrence.json` after it loads.
- Loading state: graph canvas shows `Cargando red…` centred in stone-400, no spinner. Transitions to graph render when JSON is available.

### Transition from starter to filtered (Claude's discretion)

- When the user types a search query or applies a facet, the graph does not replace its node set — it suppresses non-matching nodes in place. This preserves spatial context.
- If the filtered result set is empty, all nodes are suppressed and a centred label reads: `Sin resultados en la red para esta búsqueda`.
