## Summary

Phase 10.2 targets three surfaces: the place explorer (`src/explorar/lugares.njk` + `src/js/place-explorer.js`), place detail pages (`src/lugar.njk` + `src/js/place.js`), and entity detail pages (`src/entidad.njk` + `src/js/entity.js`). The work is split across three plans because each surface has a distinct concern.

The primary technical challenge is adapting the entity explorer's CSS grid layout and JS class architecture to the place explorer — the data model is different (MapLibre map instead of a graph canvas, Pagefind places index instead of entities, place records instead of entity records), but the sidebar + selected-card + viewport-filter pattern is directly reusable. The selected-place card in the sidebar mirrors the `highlightEntity` card in `entity-explorer.js`.

The Protomaps CDN switch is straightforward: replace the `style` string in two `maplibregl.Map({...})` calls. The terrain-only layer stripping requires a custom style JSON object using the `@protomaps/basemaps` CDN package rather than a plain URL — the style URL endpoint returns the full style and there is no server-side layer-filter parameter. Click-to-pin tooltips for place detail pages require a custom positioned `div` (not MapLibre's `Popup`) pinned to map coordinates, with a close button.

The entity detail page changes are pure JS: the `buildRoleFilters` function (entity.js line 168) is replaced with a grouped accordion that reuses the `roleGroups` taxonomy and `renderFocalRoleFacet` pattern already in `entity-explorer.js`. The focal node colour fix is a one-line change to the `renderGraph` function where the central entity node is created (entity.js line 259–265). The "Ver en explorador" button already exists in `entidad.njk` line 143, but the URL uses `/entidades/?entidad=` which matches D-14's requirement — the plan needs to verify and possibly tighten this.

**Primary recommendation:** Build plan 10.2-01 (place explorer) first as it is the most complex. Plans 10.2-02 and 10.2-03 are shorter and can be written after 10.2-01 is understood.

### Protomaps CDN — Key Facts

[VERIFIED: docs.protomaps.com, protomaps.com/api]

- **Style URL format:** `https://api.protomaps.com/styles/v5/light/en.json?key=MY_KEY`
- **API key required:** Yes — obtained from the Protomaps dashboard. Free for non-commercial use. CORS is configured per key; localhost bypasses CORS.
- **Layer filtering:** The CDN style URL returns the full style (all layers). To strip roads/buildings/POIs/landuse, the plan must use the `@protomaps/basemaps` CDN package and build a custom style object that calls `basemaps.layers(...)` with a custom layer array (or post-filter the returned layers array).

The `@protomaps/basemaps` CDN package exposes:
```javascript
// Load from CDN (no npm required — consistent with Tailwind standalone approach)
// <script src="https://unpkg.com/@protomaps/basemaps@5/dist/basemaps.js" crossorigin="anonymous"></script>
basemaps.layers("protomaps", basemaps.namedFlavor("light"), { lang: "es" })
// Returns an array of MapLibre layer definitions — filter this array by layer id
```

**Terrain-only layers to keep** (per Protomaps layer reference [VERIFIED: docs.protomaps.com/basemaps/layers]):
- `earth` — land polygons
- `water` — water polygons, lines, point labels
- `boundaries` — country/region/county/locality boundaries
- `places` — place name labels

**Layers to remove:**
- `roads` / `transit`
- `buildings`
- `pois`
- `landuse` / `landcover`

The filtering approach: call `basemaps.layers(...)` to get the full layer array, then filter by checking which layer's `source-layer` or `id` prefix matches the remove list.

**Installation / loading:**
```html
<!-- In lugar.njk / lugares.njk <head> block -->
<script src="https://unpkg.com/@protomaps/basemaps@5/dist/basemaps.js" crossorigin="anonymous"></script>
```

### Pattern 5: Protomaps Terrain-Only Style Object

Both `place-explorer.js` (line 215) and `place.js` (line 304) currently set:
```javascript
// [VERIFIED: src/js/place-explorer.js line 215]
style: 'https://tiles.openfreemap.org/styles/liberty',
```

The replacement style object:
```javascript
// Source: docs.protomaps.com/basemaps/maplibre (VERIFIED)
const API_KEY = 'YOUR_KEY';  // stored in a shared constant or env-like variable
const allLayers = basemaps.layers('protomaps', basemaps.namedFlavor('light'), { lang: 'es' });
const REMOVE_SOURCE_LAYERS = new Set(['roads', 'transit', 'buildings', 'pois', 'landuse', 'landcover']);
const terrainLayers = allLayers.filter(l => !REMOVE_SOURCE_LAYERS.has(l['source-layer']));

const style = {
  version: 8,
  glyphs: 'https://protomaps.github.io/basemaps-assets/fonts/{fontstack}/{range}.pbf',
  sprite: 'https://protomaps.github.io/basemaps-assets/sprites/v4/light',
  sources: {
    protomaps: {
      type: 'vector',
      url: `https://api.protomaps.com/tiles/v4.json?key=${API_KEY}`,
      attribution: '<a href="https://protomaps.com">Protomaps</a> © <a href="https://openstreetmap.org">OpenStreetMap</a>'
    }
  },
  layers: terrainLayers
};
```

The `basemaps` global is available after the CDN script tag loads. The API key needs to be stored somewhere — a `const PROTOMAPS_API_KEY` at the top of each JS file, or a shared data attribute on the container element. [ASSUMED: the project has no existing secrets-in-JS convention; check how other keys are handled, or simply hardcode in JS since this is a frontend-only key with CORS restriction as the security model.]

## Common Pitfalls

### Pitfall 1: Protomaps layer filtering by `source-layer` vs `id`
**What goes wrong:** Some Protomaps layers have `source-layer` as their tile source layer (e.g., `roads`), but the generated MapLibre layer objects may have an `id` like `roads_minor` or `roads_highway`. Filtering only on `source-layer` may miss layers. Alternatively, filtering only on `id` prefix is fragile if naming conventions change.
**How to avoid:** Filter on `source-layer` as the primary key (it maps 1:1 to the Protomaps tile layers). Inspect the output of `basemaps.layers(...)` in a browser console to verify which `source-layer` values are returned before writing the filter condition.
**Warning signs:** Map appears blank or shows roads/buildings despite filtering.

### Pitfall 2: `@protomaps/basemaps` CDN script not loaded before map init
**What goes wrong:** `basemaps` global is undefined when `new maplibregl.Map({style: ...})` runs.
**How to avoid:** Ensure the `@protomaps/basemaps` script tag appears **before** the map initialisation code, or wait for the `load` event if using async loading. In `lugar.njk` and `lugares.njk`, the MapLibre CSS/JS and pmtiles module are loaded in `{% block head %}` — add the basemaps script there too, not in `{% block scripts %}`.

### Pitfall 3: Place explorer grid layout and current `.container` wrapping
**What goes wrong:** The current `lugares.njk` wraps the explorer in `<div class="container font-sans">` which constrains width. The entity explorer uses `.explorer-page` (which has its own `max-width`). If the place explorer switches to `.explorer-page` but keeps the `.container` wrapper, the grid will be double-constrained or offset.
**How to avoid:** The place explorer template needs to drop the `.container` wrapper and use `.explorer-page` directly, matching `entidades.njk`.

### Pitfall 4: Selected place card obscures mobile map area
**What goes wrong:** The entity explorer's 3-column grid collapses on mobile (`main.css` line 3217+). If the selected place card is in a fixed `selected` grid area, on mobile it may overlap the map or disappear.
**How to avoid:** Follow the existing mobile breakpoint rules already defined for `.explorer-grid` in `main.css`. The mobile layout should stack: map → filters → results (place index). The selected place card can appear inline above the index on mobile.

### Pitfall 5: `entityCode` variable scope in entity.js role accordion
**What goes wrong:** The `buildRoleFilters` function in `entity.js` is a nested function inside the main `DOMContentLoaded` closure. The replacement accordion function needs access to `links`, `activeRoles`, and `applyFilters()` from the same closure — if the accordion re-renders itself (for state updates), it must call `applyFilters()` directly, not `buildRoleFilters()` again.
**How to avoid:** Write the accordion as a closure that captures `links` and `activeRoles` by reference, or pass them as parameters. Do not call `buildRoleFilters()` recursively; instead, use partial re-render (replace the accordion `div`'s innerHTML).

### Pitfall 6: Focal node colour — Spanish label mapping
**What goes wrong:** `place.js` line 255 maps `eType === 'institución'` → `'corporate_body'` but `ui.entity.types` may use a different Spanish label for `family` entities. If the label for `family` is `'Familia'` and the code only handles `'persona'` and `'institución'`, family entities will get the wrong colour.
**How to avoid:** Read `src/_data/ui.js` to get the canonical Spanish labels for all three entity types before writing the `mappedType` mapping. Add all three branches.

### Pitfall 7: MapLibre Popup vs. custom tooltip div
**What goes wrong:** MapLibre's built-in `Popup` is anchored to geographic coordinates and scrolls with the map. A click-to-pin tooltip built with `map.project()` and absolute CSS positioning does NOT stay anchored when the user pans — it must be dismissed on map `move` or manually repositioned.
**How to avoid:** On place detail pages, panning after clicking the marker should either (a) keep the tooltip open but update its position on `map.on('move', ...)`, or (b) dismiss the tooltip on move. D-08 says "click-to-pin" — approach (b) is simpler and consistent with the close-button pattern. Dismiss on `map.on('movestart')`.

### Terrain-Only Protomaps Style

```javascript
// Source: docs.protomaps.com/basemaps/maplibre [VERIFIED]
// Prerequisite: <script src="https://unpkg.com/@protomaps/basemaps@5/dist/basemaps.js"></script>
var PROTOMAPS_KEY = 'YOUR_KEY_HERE';
var TERRAIN_SOURCE_LAYERS = new Set(['roads', 'transit', 'buildings', 'pois', 'landuse', 'landcover']);

function buildTerrainStyle() {
  var allLayers = basemaps.layers('protomaps', basemaps.namedFlavor('light'), { lang: 'es' });
  var terrainLayers = allLayers.filter(function(l) {
    return !TERRAIN_SOURCE_LAYERS.has(l['source-layer']);
  });
  return {
    version: 8,
    glyphs: 'https://protomaps.github.io/basemaps-assets/fonts/{fontstack}/{range}.pbf',
    sprite: 'https://protomaps.github.io/basemaps-assets/sprites/v4/light',
    sources: {
      protomaps: {
        type: 'vector',
        url: 'https://api.protomaps.com/tiles/v4.json?key=' + PROTOMAPS_KEY,
        attribution: '<a href="https://protomaps.com">Protomaps</a> © <a href="https://openstreetmap.org">OpenStreetMap</a>'
      }
    },
    layers: terrainLayers
  };
}
```

### Click-to-Pin Tooltip for MapLibre Marker (place detail page)

```javascript
// Source: MapLibre GL JS docs + entity.js graph-tooltip pattern [ASSUMED pattern; VERIFIED entity.js]
var activeTooltip = null;

function showMapTooltip(map, mapContainer, lngLat, html) {
  dismissMapTooltip();
  var tooltip = document.createElement('div');
  tooltip.className = 'graph-tooltip map-tooltip';  // reuse graph-tooltip CSS
  tooltip.innerHTML = html;

  var closeBtn = document.createElement('button');
  closeBtn.type = 'button';
  closeBtn.className = 'graph-tooltip-close';
  closeBtn.textContent = '\u00D7';
  closeBtn.addEventListener('click', dismissMapTooltip);
  tooltip.insertBefore(closeBtn, tooltip.firstChild);

  var pt = map.project(lngLat);
  tooltip.style.position = 'absolute';
  tooltip.style.left = pt.x + 'px';
  tooltip.style.top = pt.y + 'px';
  mapContainer.style.position = 'relative';
  mapContainer.appendChild(tooltip);
  activeTooltip = tooltip;

  // Dismiss if user pans away
  map.once('movestart', dismissMapTooltip);
}

function dismissMapTooltip() {
  if (activeTooltip) { activeTooltip.remove(); activeTooltip = null; }
}
```
