**Checkbox race condition fix (D-19):**

1. Add `this._searchGen = 0` to the constructor alongside the existing state properties (around line 33).

2. At the top of the `search()` method (line 492), add:
```javascript
const gen = ++this._searchGen;
```

3. After every `await` in `search()` (after `await this.pagefind.search(...)` at ~line 507, and after `await Promise.all(...)` at ~line 535 and ~line 548), add a stale check:
```javascript
if (gen !== this._searchGen) return;
```

This prevents a slow in-flight search from calling `renderFacets()` after a newer search has already started, which is what causes checkboxes to revert.

**Map-filter sync (D-08):**

4. In the `search()` method, change the `updateMap` call at line 563 from:
```javascript
this.updateMap(this.allPlaces);
```
to:
```javascript
// Filter map markers to match search results (D-08)
if (this.state.q || this.state.type.length || this.state.hasCoords !== null || this.state.hasAuthority !== null) {
  // Extract place IDs from Pagefind results via URL pattern /nl-{id}/
  var matchingIds = new Set();
  for (var ri = 0; ri < allResults.length; ri++) {
    var url = allResults[ri].url || '';
    var match = url.match(/\/nl-(\d+)\//);
    if (match) matchingIds.add(parseInt(match[1], 10));
  }
  var filteredPlaces = this.allPlaces.filter(function(p) { return matchingIds.has(p.id); });
  this.updateMap(filteredPlaces);
} else {
  this.updateMap(this.allPlaces);
}
```

Note: `allResults` is `searchResult.results` which contains stub objects with a `.url` property -- no need to call `.data()`. The `url` field is available immediately from Pagefind search stubs. Verify this by checking that `searchResult.results[0]` has a `.url` property; if it does not, fall back to resolving result data. The Pagefind search stubs in this project expose `.url` (confirmed by how `renderResults` uses `hit.url` after resolving via `.data()` -- but the URL is also on the stub itself per Pagefind API).
