<threat_model>
ASVS Level 1 assessment:
- **CuratedEntityGraph fetches**: Loads `/data/curated-entity-graph.json` (same-origin static file) and entity-link shards from `/data/entity-links/{code}.json` (same-origin static files). No user-controlled URLs. No injection vector.
- **?nodo= parameter**: Read from URL via `URLSearchParams.get('nodo')`. Used only to find a matching node ID in the pre-loaded graph data (string comparison against node.id). Not used in DOM innerHTML, fetch URLs are constructed from the matched node's known-safe `id` field, not directly from the URL parameter. No XSS vector.
- **Entity detail page link**: Template outputs `{{ ent.entity_code }}` which is an alphanumeric code from build-time data, not user input. No injection.
No high-severity threats identified.

Create `src/js/curated-entity-graph.js` with a `CuratedEntityGraph` class. This replaces `EntityNetworkGraph` entirely.

**Constructor:** `constructor(container)` — stores container reference, initialises empty state. Does NOT call init() in constructor (unlike the old class) — init is called explicitly after DOM is ready.

**`async init()` method:**
1. Create DOM structure inside `this.container`:
   - A `div.graph-canvas` element for force-graph (id: `curated-graph-canvas`)
   - A `div.graph-legend` below it with legend items for person (burgundy `#8B2942`), corporate body/family (blue `#6666BB`)
   - A `div.graph-message` element (hidden by default) for fallback messages
2. Fetch `/data/curated-entity-graph.json`. On fetch failure, show "No se pudo cargar la red de entidades." in graph-message and return.
3. Store the fetched data as `this.graphData`.
4. Initialise force-graph:
```javascript
this.fg = new ForceGraph(canvasEl)
  .graphData({ nodes: this.graphData.nodes, links: this.graphData.links })
  .cooldownTicks(0)
  .d3AlphaDecay(1)
  .nodeId('id')
  .nodeLabel(n => `${n.label} (${n.degree} conexiones)`)
  .nodeColor(n => this._nodeColor(n))
  .nodeVal(n => Math.max(3, Math.sqrt(n.degree) * 0.5))
  .linkWidth(l => Math.max(0.5, Math.sqrt(l.weight) * 0.3))
  .linkColor(() => 'rgba(160, 152, 136, 0.3)')
  .onNodeClick(node => this._onNodeClick(node))
  .onNodeHover(node => this._onNodeHover(node))
  .width(canvasEl.clientWidth)
  .height(300);
```
5. Check for `?nodo=` URL parameter: `new URLSearchParams(window.location.search).get('nodo')`. If present, call `this._centreOnEntity(nodoCode)`.

**`_nodeColor(node)` method:**
Return `#8B2942` for `type === 'person'`, `#6666BB` for `corporate_body` or `family`. Use the same colour map as EntityNetworkGraph (lines 30-34 of entity-network-graph.js).

**`_centreOnEntity(code)` method:**
1. Find node in `this.graphData.nodes` where `node.id === code`.
2. If found: `this.fg.centerAt(node.x, node.y, 800)` then `this.fg.zoom(5, 800)`. Visually highlight the node by adding it to a `this.highlightedNodes` Set and triggering a re-render.
3. If NOT found: Show fallback message in `div.graph-message`: `"Esta entidad no aparece en la vista de red curada (muestra las entidades con mas vinculos)."` with a link back to the entity detail page: `<a href="/entidad/${code}/">Ver ficha completa</a>`. Use `textContent` for the message text and create the anchor element with DOM API (not innerHTML with the raw code parameter) to avoid any XSS concern.

**`_onNodeClick(node)` method:**
1. If node has already been expanded (tracked in `this.expandedNodes` Set), navigate to entity detail page: `window.location.href = '/entidad/' + node.id + '/'`.
2. If node has NOT been expanded, trigger ego-network expansion:
   a. Add node.id to `this.expandedNodes`
   b. Fetch `/data/entity-links/${node.id}.json` — this is the entity's link shard
   c. From the shard, extract unique entity codes that are NOT already in the graph
   d. For each new entity code, create a node: `{ id: code, label: displayName, type: type, degree: 0, x: node.x + (Math.random() - 0.5) * 50, y: node.y + (Math.random() - 0.5) * 50 }`
   e. For the display name and type of new nodes: check if the entity exists in `this.graphData.nodes` first; if not, use the `entity_code` as label and `'unknown'` as type (the shard has `entity_code` and `role` but not always `display_name` — look up from desc-entity-lookup.json or use code as fallback)
   f. Create new links between the clicked node and each new neighbour
   g. Update force-graph: `this.fg.graphData({ nodes: allNodes, links: allLinks })`
   h. After expanding, set `cooldownTicks` to a small value (e.g., 50) so the new nodes settle near the clicked node, then reset to 0
3. Limit expansion to max 20 new nodes per click to prevent overwhelming the graph.

**`_onNodeHover(node)` method:**
Update cursor style: `this.container.style.cursor = node ? 'pointer' : 'default'`.

**`setExplorer(explorer)` method:**
Store reference. The curated graph does NOT interact with the explorer's search state (per research finding #4 — graph and list are independent panels). This method exists for API compatibility but the reference is unused in the curated graph.

**Style notes:**
- Use vanilla JS (no classes from entity-network-graph.js that depend on shard-driven data)
- No `import` statements — this is a plain script loaded via `<script>` tag (matches codebase pattern)
- The class is exposed as a global: `window.CuratedEntityGraph = CuratedEntityGraph` or just declared at top level
